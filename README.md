# AURA — Midnight selective-disclosure survey dApp

AURA is a React/Vite dApp for deploying and reading eligibility-gated survey contracts on Midnight Preview and Preprod. The browser uses 1AM's DApp Connector to prove, balance, sign, and submit. It does not create a wallet, contract address, transaction hash, ballot, credential, or balance locally.

## Privacy model / Privacy Claim

### What an observer can learn

- The contract address, transaction identifiers/hashes, title SHA-256 commitment, selected network, eligibility threshold, total ballot count, and option counters.
- In this contract, the ballot option is **explicitly disclosed** with `disclose(opt)` before its public tally changes. An observer can learn the selected option.

### What an observer and AURA cannot learn

- The `eligibility_score()` witness used by the Compact assertion.
- 1AM private keys, shielded keys, proof preimages, or the wallet's internal coin selection.
- Any score or credential value generated by a demo fallback: there is no such fallback in this repository.

### Important limitation

This is an eligibility-gated **public-choice** survey, not a secret-ballot protocol. Compact correctly requires the disclosure because a public counter is changed conditionally on `opt`. A secret-ballot version needs a separately designed and audited commitment, anti-replay/nullifier, credential-attestation, aggregation, and controlled-release protocol. Do not use this contract for elections or any setting that promises vote secrecy.

### Credential integrity

Confidentiality alone does not make a score trustworthy. AURA therefore refuses to synthesize an eligibility score. Production voting remains gated until a trusted issuer provides holder-bound, expiry/revocation-aware credentials whose witness is evaluated locally by the prover. See [`docs/product-proposal.md`](docs/product-proposal.md).

## Real 1AM transaction flow

1. A user selects Preview or Preprod and connects 1AM.
2. AURA calls `connect(networkId)`, reads the wallet's indexer configuration, unshielded address, and actual DUST balance.
3. The compiler-generated Compact binding and ZK artifacts are loaded from `managed/anonymous_survey/`.
4. 1AM provides proof generation; Midnight.js builds the transaction.
5. 1AM balances, signs, and submits the serialized transaction.
6. Midnight.js waits for indexer finalization and returns the canonical contract address, transaction ID, and transaction hash.
7. AURA records only those finalized public values for the active browser session; team-visible contracts are configured explicitly through Vercel environment variables.

The frontend uses official Midnight packages including `@midnight-ntwrk/midnight-js-indexer-public-data-provider`, `@midnight-ntwrk/midnight-js-dapp-connector-proof-provider`, `@midnight-ntwrk/midnight-js-fetch-zk-config-provider`, and `@midnight-ntwrk/midnight-js-contracts`.

## 1AM, Preview faucet, and DUST buffer

1. Install and unlock [1AM Wallet](https://chromewebstore.google.com/detail/1am/bphnkdkcnfhompoegfpgnkidcjfbojjp).
2. Select the same network in 1AM and AURA.
3. For Preview, use the [Preview tNIGHT faucet](https://faucet.preview.midnight.network), then register received tNIGHT in 1AM to generate tDUST.
4. AURA requires the wallet-reported balance to include a 30 DUST safety buffer after a 12 DUST estimate. The wallet's final fee and sponsorship decision is authoritative.

Wallet errors and disconnect controls are visible in **Network & wallet readiness** and **Profile**. No demo wallet button exists.

## Local development, compilation, tests, and CI

Prerequisites: Node 22+, a current [Compact toolchain](https://docs.midnight.network/compact), and (for live calls) 1AM.

```bash
npm ci
compact compile contracts/anonymous_survey.compact managed/anonymous_survey
npm run contract:check
npm test
npm run build
npm run dev
```

The CI workflow installs Compact, compiles the committed source to a clean temporary directory, validates the committed generated artifacts, runs tests, and builds Vite on every push/PR. It does not deploy to Vercel or spend tokens.

## Vercel configuration

Vercel serves the generated ZK keys and binary ZKIR through Vite's `publicDir: 'managed'`; the client retrieves only public compiler artifacts. It does not need, accept, or store a wallet private key. Configure these public values only when you want read-only indexer access before a user connects 1AM:

```dotenv
VITE_MIDNIGHT_PREVIEW_INDEXER_URI=https://<preview-indexer>/graphql
VITE_MIDNIGHT_PREVIEW_INDEXER_WS_URI=wss://<preview-indexer>/graphql
VITE_MIDNIGHT_PREPROD_INDEXER_URI=https://<preprod-indexer>/graphql
VITE_MIDNIGHT_PREPROD_INDEXER_WS_URI=wss://<preprod-indexer>/graphql
VITE_MIDNIGHT_DUST_BUFFER=30
VITE_AURA_SURVEY_CONTRACTS_JSON=[]
```

Prefer the connector-provided URLs when connected: they respect the user's wallet privacy and service choices. Never set a seed phrase, private key, eligibility score, or credential payload in Vercel variables.
